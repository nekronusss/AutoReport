# Участие в разработке AutoReport

Сначала поднимите локальное окружение по [README](README.md). Контракт источника и правила публикации описаны в [документации](docs/data-contract.md).

## Сообщить о проблеме

Создайте [issue](https://github.com/nekronusss/AutoReport/issues) с командой запуска, профилем конфигурации, ожидаемым и фактическим результатом. Для ошибки загрузки приложите период, код завершения и обезличенный вывод `status`. Укажите ОС, версии Python/PostgreSQL или Docker/Compose.

Используйте синтетический пример. Не прикладывайте секреты из `secrets/`, реальные заказы, дампы БД и конфигурацию с паролями.

## Подготовить изменение

Создайте ветку от `main`, внесите изменение и добавьте проверку затронутого поведения. Изменения формата входных данных, CLI и конфигурации сопровождайте документацией. Проверяйте сохранение предыдущей публикации при ошибке новой поставки; не меняйте расчёты только ради прохождения теста.

```sh
uv sync --frozen
uv run ruff check src tests
uv run mypy src/dqflow
uv run pytest -q tests/unit
```

Для изменений SQL, загрузки, публикации и восстановления нужен полный набор с `DQFLOW_INTEGRATION=1` на отдельной мигрированной БД. Команды есть в [README](README.md#проверки). `uv.lock` обновляйте вместе с изменениями зависимостей.

В pull request опишите исходную проблему, новое поведение и выполненные проверки. Если проверка требует внешнего источника или production-стенда и не выполнялась, укажите это прямо.
