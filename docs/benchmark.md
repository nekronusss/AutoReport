# Фактические замеры · 08.10.2026

20 последовательных полных обработок 200 000 строк, seed=42, один неизменяемый
snapshot `54c03c429895e0c44f1aee5debac3019`. Источник HTTP на localhost, PostgreSQL
18.1 native, Windows 11 10.0.26200, 16 логических CPU, 15.2 GiB RAM.
Это рабочая машина, **не изолированный приёмочный Linux-стенд 4 vCPU / 8 GiB**.
Docker-лимиты CPU/RAM не применялись.

Каждый повтор получил отдельный dataset/config identity и реально выполнил
extract, SHA-256, raw COPY, typed COPY, 20 правил, dbt build + 10 SQL-тестов,
независимую сверку, транзакционную публикацию и HTML/CSV/JSON. Ни одного no-op.
Данные предыдущих повторов сохранялись, БД росла в ходе серии.

процесса не объявляется измерением полностью холодного диска.
RSS опрашивался раз в 50 мс; память PostgreSQL и source API в эту величину не входит.

и исправлена поддержка допустимых дефисов/подчёркиваний CSV snapshot_id.

Первичная серия до обновления библиотек сохранена как benchmark-initial-20.json и
не смешивается с этой выборкой.

Цели ТЗ (600 с / 120 с / 2048 MiB) на этой машине не превышены. Это **не подтверждает**
их выполнение на заданном production hardware; повторить серию в выделенной среде.
На машине параллельно работали обычные фоновые процессы; часть времени выполнялись
чтение метаданных и подготовка артефактов. Benchmark и integration-тесты на БД не запускались одновременно.

## Baseline

Команда `dqflow benchmark --rows 200000 --repeat 1 --baseline` заменяет typed COPY
на последовательные INSERT. Raw COPY, правила, SQL-модели и отчёты те же.
Результат отдельного контрольного прогона — [baseline.json](evidence/baseline.json):
**100.22 с** полный цикл, **13.55 с** блок качества, **236.60 MiB** максимальный RSS.
Один baseline-повтор не даёт надёжной оценки его p95 или распределения ускорения.

## Воспроизведение

```powershell
$env:DQFLOW_CONFIG='config/benchmark.yaml'
uv run dqflow benchmark --rows 200000 --repeat 20
uv run dqflow benchmark --rows 200000 --repeat 1 --baseline
```

Профиль benchmark.yaml предназначен для отдельной БД dqflow_benchmark; сначала
создать её, bootstrap-roles и migrate. Для Docker/Linux указать конфигурацию
контейнерного источника/БД и лимиты; сохранить версии, характеристики диска,
background load, исходные samples и отдельный холодный запуск.
